# z-only reward head — seed 12345 continuous (Sep 2026, RTX 3080)

The mechanism test called for at the end of `wm_checkpoints/zonly_12345_5090/README.md`:
the same reward-head ablation, but run on the substrate that actually collapses.
The `[h, z]` control for this arm is `wm_checkpoints/v7_12345_continuous`
(peak +99.0 @ ep 160, final-10 −31.9).

| Field | Value |
|---|---|
| Train seed | 12345 |
| Protocol | Single continuous 500-epoch run (no resume, no optimizer reset) |
| Data | Human `lunarlander_{train,val}_dataset.npz` |
| Config | `config_zonly.yaml` — identical to `config.yaml` plus `world_model.reward_head_input: z` |
| Reward head | `nn.Linear(16, 256)` first layer (`latent_dim` only) vs `nn.Linear(272, 256)` for `[h, z]` |
| GPU | RTX 3080 |
| Checkpoints | 100 files, epochs 5–500, stride 5 |
| MPC outcome | **Collapse not prevented.** Large drawdown with the same post-300 slope as the control; endpoint less negative. |

Implementation is identical to the 5090 arm — a genuine truncation of the head's
input rather than a zero mask, swapped in after `__init__` so the RNG stream is
undisturbed, with the variant inferred from `reward_head.0.weight` width at load
time. See the 5090 README for details.

## Headline

The ablation did **not** prevent the collapse. If reward information migrating
into `h` were the mechanism, removing `h` from the head should have stopped it.
It did not.

MPC sweep, 20 episodes per checkpoint at eval seed 12345, MA-7 smoothed:

All statistics over epochs > 50; peak and drawdown on the MA-7 curve, final-10 on
raw checkpoint means. Reproduce with `python results/figures/make_zonly3080_figures.py`.

| run | MA-7 peak | final-10 | drawdown | ρₛ(epoch, MA-7), ep > 300 |
|---|---:|---:|---:|---:|
| **z-only 12345, 3080 (this run)** | **+107.7 @ ep 240** | **+15.1** | **109.2** | **−0.87** |
| `[h, z]` V7 12345, 3080 (control) | +99.0 @ ep 160 | −31.9 | 156.8 | −0.88 |
| `[h, z]` 12345, paper, resume @ 300 | +153.0 @ ep 310 | +61.7 | 111.2 | −0.65 |
| z-only 12345, 5090 | +143.0 @ ep 305 | +124.1 | 55.7 | +0.29 |
| `[h, z]` 777, 3080 (healthy reference) | +199.2 @ ep 495 | +189.1 | 47.6 | +0.94 |

The decisive comparison is the last column. The post-300 decline of the z-only
arm (−0.87) is indistinguishable from its `[h, z]` control (−0.88). The run
still sheds 109 points from its peak, and `analyze_llc.py` flags
`collapse-present: True` for it exactly as it does for the control.

What did change is the endpoint: +15.1 against −31.9, and the peak arrives 80
epochs later. So the ablation shifts the level and delays the onset without
touching the decay itself. That is the signature of a nuisance parameter, not of
a mechanism.

## The intervention did work at the representation level

This is not a null because the ablation failed to bite. ROF responds exactly as
the theory says it must when `h` is removed from the reward head — mean over
epochs ≥ 400:

| arm | val_loss | post_rew_rmse | ROF |
|---|---:|---:|---:|
| z-only 3080 (this run) | 32.78 | 5.139 | **0.2841** |
| `[h, z]` V7 3080 (control) | 33.68 | 5.219 | **0.1957** |
| z-only 5090 | 32.68 | 5.130 | 0.2799 |
| `[h, z]` 777 (healthy) | 35.98 | 5.398 | 0.2234 |

ROF rises from 0.196 to 0.284 under the ablation, on the same seed and the same
GPU. The knob turned. The closed-loop outcome did not follow.

Note the `777` row against the MPC table above: it has the **worst** validation
loss of the four arms (35.98) and by far the **best** closed-loop return
(+174.1). Validation loss inverts the ranking it is supposed to provide.

## ROF drawdown gate: a false negative

Run through the gate and the early-warning detector from `results/`:

| run | good_dd | bad_dd | either | gate | early warning |
|---|---:|---:|---:|---|---|
| **z-only 12345 3080 (this run)** | 0.0072 | 0.0165 | **0.0165** | **quiet** | does not fire |
| `[h, z]` 12345 V7 3080 (control) | 0.0642 | 0.0405 | 0.0642 | FIRE | fires @ 120, lead 40 |
| z-only 12345 5090 | 0.0070 | 0.0064 | 0.0070 | quiet | does not fire |
| `[h, z]` 12345 paper resume @ 300 | 0.0609 | 0.0343 | 0.0609 | FIRE | fires @ 130, lead 180 |
| `[h, z]` 777 3080 (healthy) | 0.0264 | 0.0066 | 0.0264 | quiet | fires @ 110, gated out |

The gate is quiet at 0.0165, well under the 0.05 threshold, on a run that lost
109 points of closed-loop return from its peak. On the 5090 arm quiet was the
correct verdict because that run recovered to +124. Here it is not: this run
ends at +15.1 having peaked at +107.7. **This is a false negative**, and it is
the first one in the panel where the drawdown is unambiguous.

## What this run does and does not settle

**Settles:** reward-information migration through `h` is not the mechanism of
collapse on this substrate. The ablation removed the pathway, ROF confirmed the
removal, and the collapse slope was unchanged.

**Settles:** the ROF drawdown gate produces false negatives on genuine
drawdowns, not only on recovering runs.

**Does not settle:** what the mechanism actually is. The pattern here — rise,
peak, sustained decline, insensitive to reward-head architecture, sensitive to
seed and GPU — is consistent with the edge-of-reach account of offline
model-based RL ("The Edge-of-Reach Problem in Offline Model-Based Reinforcement
Learning", NeurIPS 2024), in which the planner progressively
seeks states whose values are never corrected by the data and the failure
compounds each epoch. That account predicts the pathology lives in *where the
planner goes*, not in any parameter of the model, which would explain why no
model-internal statistic in our panel detects it. Untested here.
